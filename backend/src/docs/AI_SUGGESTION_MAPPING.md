AI Suggestion → Roadmap Mapping (Backend)

Purpose
- 문서화: OpenAI/AI 제안(Suggestion)의 changeJson을 어떻게 Roadmap 노드/엣지로 매핑하는지 정의합니다.
- 프론트엔드와 계약: 프론트는 preview/실제 반영 결과에 대해 예상 가능한 필드를 사용합니다.

High-level rules
1. Suggestion.changeJson formats accepted
   - Single JSON object describing one node, e.g.
     { "label": "Login API", "aiSummary": "해당 API는 ...", "status": "todo", "progress": 0 }
   - JSON array of node objects: first element treated as root, remaining as children. e.g.
     [ {"title":"Root"}, {"title":"Child 1"}, {"title":"Child 2", "assignees":["Alice"]} ]
   - Object with `nodes` or `items` array: same as array handling above.

2. Field mapping (from suggestion → RoadmapNodeDto)
   - title or label → label
   - aiSummary or summary → aiSummary
   - status → status (defaults to 'todo')
   - progress → progress (defaults to 0)
   - assignees (array) → assignees (list of strings)
   - Any missing fields are filled by RoadmapService.createNode defaults (code, dueDate, tier, size, etc.)

3. Approve behavior
   - If changeJson is an array/nodes/items: create root (or update existing targetId if provided), then create children and edges root→child.
   - If changeJson is a single object and Suggestion.targetId is provided: update that node with provided fields.
   - Duplicate prevention: suggestions with the same sourceId that already have status=APPROVED are not applied again.

4. Regeneration with user feedback
   - A rejected or unsatisfactory suggestion can be regenerated by sending a feedback string to POST /api/teams/{teamId}/suggestions/{id}/regenerate.
   - The backend resolves the original spec from the sourceId, passes the original spec + user feedback to the AI service, and creates a new set of suggestion cards.
   - The regenerated suggestion bodies should include the user's feedback so the final approval loop remains human-controlled.

API Endpoints (backend)
- POST /api/teams/{teamId}/specs  → submit spec (triggers AI suggestions)
- GET /api/teams/{teamId}/specs/{specId}/suggestions → list suggestions from spec
- GET /api/teams/{teamId}/specs/{specId}/preview → preview generated roadmap graph from suggestions (no DB changes)
- POST /api/teams/{teamId}/suggestions/{id}/approve → approve suggestion and apply changes
- POST /api/teams/{teamId}/suggestions/{id}/regenerate → create revised suggestions using user feedback

Frontend expectations
- Roadmap nodes returned by /api/teams/{teamId}/roadmap must include at least: id, label, status, progress, aiSummary, assignees, tier, x,y,w,h, comments, files.
- createNode will populate defaults for missing properties; backend ensures aiSummary/label/assignees/status/progress are set when produced from AI.

Example suggestion payload (array)
[
  { "title": "Implement Auth", "aiSummary": "로그인·회원가입 API 구현", "assignees": ["Sam"] },
  { "title": "OAuth Integration", "aiSummary": "Google OAuth 연동" }
]

Notes
- For production LLM output, ensure the AI is instructed to return strictly-typed JSON (see OpenAIService system prompt).
- Consider adding stricter JSON Schema validation for changeJson in future iterations.
